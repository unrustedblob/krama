## Not filed

- **Accumulation stops at the type.** The plan was to report every independent problem in one go.
  An invalid type exits at once, so `foo(bar,baz,qux): x` reports only the type, though the scope
  vocabulary and count do not depend on it. The rules that do depend on the type (`build`, `learn`,
  `test`) are right to wait for it. A design point, not a defect against COMMITS.md.
- **A merge label outside a merge gets the generic structural message.** `m1/arena: x` as an ordinary
  commit is rejected correctly, but the message does not say that the label belongs to a merge. A
  targeted hint was option 3 of the error-message discussion and was not taken.
- **The duplicate-scope message prints Python tuples** — `[('lex', 2)]`. Readable, not polished.
- **Two spaces after the colon are accepted** (`fix(lex):  x`). COMMITS.md states no rule on it.
- **The merge label is checked for shape, not identity.** Decided on this branch to build
  (label equals the merged branch's name); not yet in the hook. The header comment states the gap.
